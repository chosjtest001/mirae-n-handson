# 장애 원인 분석 (RCA)

- 대상: `incident-logs/$ARGUMENTS/`
- 결과: `docs/rca/$ARGUMENTS.md`
- 인자가 비어 있으면 `incident-logs/`의 폴더 목록을 보여 주고 사용자에게 묻는다.

## 절차

1. **수집 범위**: 파일을 통째로 읽지 않는다. `wc`, `head`, `tail`, `grep`, `awk`로 파일별 줄 수 · 기록 기간 · 시각 형식 · 타임존부터 표로 정리한다.
   - 타임존이 표기되지 않은 파일은 다른 파일과 분 단위 건수를 맞춰 근거를 적고 판단한다. 모든 시각을 한 타임존(KST)으로 맞춘다.
   - 분 단위 이상 신호를 집계해 평소 수준과 이상 구간을 나눈다. 수집 구간은 이상 구간 앞뒤로 여유를 두고(앞 30분, 뒤 15분 정도) 파일별 줄 범위로 적는다.
   - 이 단계에서는 원인을 추정하지 않는다.
2. **타임라인**: 수집 구간의 사건을 시각순 표(시각, 출처, 사건 요약, 원문 발췌)로 만든다.
   - 모든 줄에 출처를 `파일:줄번호`로 적는다. 반복 메시지는 첫 줄에 "이후 N건/분"으로 묶는다.
   - 서로 다른 파일의 같은 초 사건은 (선후 불확실)로 표시한다. 해석은 넣지 않는다.
   - 있어야 하는데 찾지 못한 기록(기동 로그, 배포 기록 등)은 따로 적는다.
3. **가설**: 서로 다른 계층(코드, DB · 쿼리, 트래픽, 인프라, 배포 · 설정)에서 2개 이상 세운다.
   - 가설마다 지지 근거(`파일:줄번호`), 반증 조건, 확인 방법(실행할 명령)을 적는다.
   - 오류 메시지 자체는 증상으로 두고, "왜 그 상태가 됐는가"를 설명하는 가설을 세운다.
4. **판정**: 먼저 로그 집계로 각 가설의 반증 조건을 확인한다. 그다음 로그의 클래스 · 스택 · 설정 값을 따라 코드와 설정 파일을 읽어 대조한다.
   - 가설마다 채택 · 기각을 판정하고 사유를 적는다. 판정에 쓴 집계는 결과와 명령을 함께 남긴다.
   - 실행하지 않은 측정, 운영과 같은지 확인하지 않은 설정은 "남은 확인 항목"으로 둔다.
5. **리포트 작성**: 다음 순서로 쓴다.
   - 요약(현상, 직접 원인, 촉발 조건, 확신 수준, 수정 방향)
   - 수집 범위 · 타임라인 · 가설과 판정(1~4단계 결과)
   - 원인(인과 순서, 직접 원인과 배경 원인)
   - 근거 로그 줄(요약 · 원인의 문장마다 `파일:줄번호`와 발췌)
   - 수정안(즉시 적용), 재발 방지(구조), 모니터링 항목(지표와 경보 기준)
   - 확인하지 못한 것(로그가 없어 판단하지 못한 부분, 다음을 위해 남겨야 할 로그)
6. **마스킹**: 리포트를 저장하기 전에 `masking-rules.md`의 규칙을 적용한다. 리포트 끝에 유형별 마스킹 건수를 한 줄로 적는다.

## 하지 말 것

- 로그에 없는 줄을 인용하지 않는다. 인용한 줄은 `sed -n '<줄번호>p'`로 원문과 대조한다.
- 가장 많이 나온 오류를 곧바로 원인이라고 부르지 않는다. 반증을 거쳐 채택한 가설만 원인으로 적는다.
- 원본 로그(`incident-logs/`)와 소스 코드를 수정하지 않는다.
- 마스킹 대응표(원문 ↔ 별칭)를 파일로 남기지 않는다.
- 마스킹 전 원본을 임시 폴더에 복사해 두지 않는다.
