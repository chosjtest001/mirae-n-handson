# 변경 영향도 분석

대상: $ARGUMENTS

## 원칙

- 코드를 고치지 않는다. 파일은 읽기만 하고 결과는 대화로 보고한다.
- 모든 항목에 `파일:줄번호` 근거를 단다. 근거를 댈 수 없는 경로는 결과에 넣지 않고 "추적 한계"에 적는다.
- 이름만 같은 다른 함수(다른 클래스의 동명 메서드, 다른 파일의 동명 함수)를 호출부로 섞지 않는다. 호출 대상이 정말 그 정의인지 include/import와 수신 객체 타입으로 확인한다.

## 절차

1. **정의 찾기**: 인자가 `파일:줄번호`면 그 줄을 포함한 함수를, 이름이면 정의를 검색한다. 정의가 여러 개면 목록을 보여 주고 사용자에게 고르게 한다. 대상이 속한 모듈명을 정한다 (`legacy/item-bank-php` → `item-bank`, `legacy/assignment-thymeleaf` → `assignment`, `legacy/grade-mssql` → `grade`).
2. **호출부 역추적**: 직접 호출부를 찾고, 그 호출부를 감싼 함수의 호출부를 다시 찾는다. 진입점(URL에 대응하는 PHP 파일, `@RequestMapping` 계열 컨트롤러 메서드, 화면 템플릿, 스케줄러 · 배치, 외부에서 부르는 프로시저)에 닿을 때까지 반복한다. 이미 방문한 함수는 다시 따라가지 않는다.
3. **테이블 찾기**: 대상 함수와 대상이 부르는 함수 · 프로시저 · 뷰가 읽고 쓰는 테이블을 SELECT / INSERT / UPDATE / DELETE로 구분한다. 뷰는 원본 테이블까지 풀어서 적는다. 스키마는 `db/mariadb/init/`, `db/mssql/init/`, 모듈 안 `sql/`도 확인한다.
4. **같은 테이블을 쓰는 코드**: 3에서 찾은 테이블 이름을 저장소 전체(`legacy/`, `modern/`, `db/`)에서 검색해 대상 외 함수를 찾고, 읽기 · 쓰기를 구분한다. 쓰는 쪽이 대상과 같은 컬럼을 건드리면 표시한다.
5. **규칙 연결**: `docs/<모듈명>/BUSINESS-RULES.md`가 있으면 근거 줄이 대상 함수 · 호출 경로 · 관련 테이블에 걸친 규칙 ID를 찾는다. 문서가 없으면 "규칙 문서 없음"이라고 적고 넘어간다. 문서의 줄번호가 현재 코드와 어긋나 보이면 그 사실을 적는다.
6. **테스트 케이스 제안**: 1~5를 바탕으로 수정 전에 현재 동작을 고정해야 할 케이스를 제안한다. 관련 규칙 ID마다 최소 1개, 영향 화면마다 정상 경로 1개를 두고, 경계값 · 빈 값 · 상태값 분기를 우선한다. `characterization/`에 이미 있는 스냅샷으로 덮이는 케이스는 그 파일을 적는다.

## 추적 한계

검색으로 호출부를 확정할 수 없는 형태가 보이면 결과와 분리해 이 절에 위치와 이유를 적는다. 예:

- PHP의 가변 함수(`$fn()`), `call_user_func`, 문자열로 만든 include 경로
- Java 리플렉션, 인터페이스 · 상속을 통한 호출, 이벤트 리스너, AOP, `@Scheduled`
- 템플릿에서의 호출(Thymeleaf 식, 폼 action 문자열), JavaScript에서 조립한 URL
- SQL의 동적 쿼리(`EXEC`, `sp_executesql`, 문자열로 만든 테이블 이름), 트리거
- 저장소 밖의 호출자(다른 시스템, 운영 배치, DB 작업 스케줄러)

## 출력 형식

```markdown
# 영향도 분석: <대상> (<정의 파일:줄번호>)

## 1. 영향받는 화면
| 화면 · URL | 진입점 근거 | 비고 |

## 2. 호출 경로
- <진입점> (`파일:줄`) → <함수> (`파일:줄`) → … → <대상> (`파일:줄`)

## 3. 영향받는 테이블
| 테이블 | 대상의 접근(R/W) | 근거 | 같은 테이블을 쓰는 다른 코드 (R/W, 근거) |

## 4. 관련 규칙 ID
| 규칙 ID | 요약 | 연결 근거 |

## 5. 수정 전에 확보할 테스트 케이스
| # | 케이스 | 입력 · 전제 | 기대 결과(현재 동작) | 관련 규칙 · 근거 |

## 6. 추적 한계
| 위치 | 형태 | 영향 가능성 |
```

빈 절은 삭제하지 않고 "해당 없음"이라고 적는다.
