# 레거시 모듈 문서화

대상: $ARGUMENTS (첫 인자는 모듈 경로, 두 번째 인자는 선택 사항인 범위 제한이다. 예: "등록 화면만")

## 원칙

- 분석 대상 폴더의 파일은 읽기만 한다. 수정 · 포맷팅 · 실행 결과 저장을 하지 않는다. 쓰기는 `docs/<모듈명>/` 아래에만 한다.
- 모든 서술에 `파일:줄번호` 근거를 단다. 근거를 댈 수 없는 내용은 "미확인 목록"에 적는다.
- 주석과 코드가 다르면 코드를 기준으로 쓰고, 주석은 비고에 남긴다.

## 모듈명 정하기

`<모듈명>`은 폴더 이름이 아니라 아래 셋 중 하나다. 목록에 없는 경로면 멈추고 사용자에게 묻는다.

| 모듈 경로 | 모듈명 |
|---|---|
| `legacy/item-bank-php` | `item-bank` |
| `legacy/assignment-thymeleaf` | `assignment` |
| `legacy/grade-mssql` | `grade` |

## 절차

각 단계가 끝나면 결과를 해당 파일에 저장한 뒤 다음 단계로 넘어간다. 저장 전에 다음 단계를 시작하지 않는다.

1. **계획 제시**: 파일 목록과 줄 수를 세고, 읽을 파일 · 읽지 않을 파일(외부 라이브러리 등) · 단계별 산출물을 제시한 뒤 사용자 확인을 받는다. 범위 제한 인자가 있으면 여기서 반영한다.
2. **진입점**: URL · 화면 · 배치 등 외부에서 호출되는 지점을 표로 정리한다. → `ARCHITECTURE.md`의 모듈 개요 · 폴더 구조 · 진입점 절에 저장.
3. **의존 관계**: include/import와 실제 함수 호출을 따라 호출 방향을 그린다. 가장 긴 함수 3개와 미확인 목록을 적는다. → `ARCHITECTURE.md`에 추가 저장.
4. **데이터 흐름**: 테이블 · 뷰 · 컬럼과 관계, 각 테이블을 읽고 쓰는 위치를 정리한다. 스키마는 모듈 폴더 밖(`db/mariadb/init/`, `db/mssql/init/`, 모듈 안 `sql/`)도 확인한다. → `ERD.md`에 저장.
5. **비즈니스 규칙 후보**: 조건문 · SQL · 검증 코드에서 규칙을 뽑아 아래 형식으로 쓴다. 주석만 근거인 내용, 매직 넘버, 같은 규칙의 중복 · 불일치는 별도 절로 모은다. → `BUSINESS-RULES.md`에 저장.
6. **표본 점검 추천**: 사람이 코드와 직접 대조할 규칙 3개를 골라 이유와 함께 제시한다. 3개 중 1개는 반드시 "가장 그럴듯해서 검증 없이 넘어가기 쉬운 규칙"으로 고른다. 나머지는 확신도가 낮은 규칙, 여러 파일에 근거가 걸친 규칙에서 고른다. → `BUSINESS-RULES.md` 끝의 "표본 점검 추천" 절에 저장하고 사용자에게도 출력한다.

## 규칙 형식

````markdown
### BR-01
- 규칙: (코드가 실제로 하는 동작을 한 문장으로)
- 근거: `search.php:522`, `db/mariadb/init/01-schema.sql:70`
- 근거 코드:
  ```php
  (근거 줄의 코드를 그대로 인용)
  ```
- 확신도: 확실 | 추정 | 불확실
- 비고: (주석과의 차이, 실행 미확인 여부, 이관 시 주의점)
````

- 모듈 내부 파일은 모듈 경로 기준, 모듈 밖 파일은 저장소 루트 기준 전체 경로로 쓴다.
- 코드와 스키마만 읽고 실제 실행하지 않은 동작은 비고에 "실행 미확인"이라고 적는다.

## 하지 말 것

오늘 `docs/item-bank` 검증 이력(BR-42)에서 실제로 문제가 된 유형이다.

- 모듈 폴더만 읽고 규칙을 확정하지 않는다. 교차 검증본은 스키마와 `docker-compose.yml`을 읽지 않아 등록 시각 규칙(BR-42)을 통째로 놓쳤다. DB 스키마 · 뷰 · 컨테이너 설정이 동작을 정하면 반드시 함께 읽는다.
- 시각 · 기본값 · 상태값 규칙을 SQL 한 줄만 근거로 쓰지 않는다. `NOW()` 한 줄만 인용하고 시각 출처(DB 서버인지 앱 서버인지), 세션 시간대 지정 여부, 컬럼 자료형과 기본값을 빠뜨려 근거를 나중에 보강했다. 값이 어디서 정해져 어떤 형태로 저장되는지까지 근거를 단다.
- 확인하지 못한 환경 값(운영 DB 시간대 등)을 로컬 설정으로 단정하지 않는다. 로컬 근거와 "운영 미확인"을 나눠 적는다.
- 교차 검증에 없는 규칙이라는 이유만으로 삭제하지 않는다. 코드로 다시 확인해 판정하고 결과를 "검증 이력"에 남긴다.
- 코드에 없는 함수 · 호출 방향 · 규칙(상식적인 중복 검사, 길이 상한 등)을 채워 넣지 않는다. 없으면 "코드에 없음"으로 적는다.
