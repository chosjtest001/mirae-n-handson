# legacy/item-bank-php 비즈니스 규칙 후보

> 선행 문서: [ARCHITECTURE.md](ARCHITECTURE.md), [ERD.md](ERD.md)
>
> 근거 표기 규칙
> - PHP 파일 경로는 `legacy/item-bank-php/` 기준이다 (예: `search.php:215`).
> - 스키마 파일은 저장소 루트 기준 전체 경로로 쓴다 (예: `db/mariadb/init/01-schema.sql:70`).
>
> 작성 원칙
> - 코드의 조건문 · SQL에서 확인한 동작만 규칙으로 올렸다. 상식이나 기대 동작으로 채우지 않았다.
> - 주석과 코드가 다르면 코드 기준으로 규칙을 쓰고 주석은 비고에 남겼다.
> - 근거가 주석뿐인 내용은 규칙으로 올리지 않고 [7. 주석만 있는 내용](#7-주석만-있는-내용)에 모았다.
> - 비고의 "실행 미확인"은 코드와 스키마를 읽어 도출했지만 실제 DB에서 돌려 보지 않은 동작이다.

## 범위 확인

- 문항 **수정** 기능은 이 모듈에 없다. `item`에 대한 `UPDATE` 문이 없고 (ERD.md 3절), 수정 화면 파일도 없다. 따라서 수정 시 검증 규칙은 뽑을 수 없다.
- 등록 시 제목 중복 검사, 지문 최대 길이 검사는 코드에 없다. 규칙으로 올리지 않았다.

## 1. 검색 대상과 조건 조합

### BR-01
- 규칙: 문항 검색의 목록과 건수는 `status = 'A'`인 문항만 대상으로 한다.
- 근거: `search.php:522`, `search.php:526`, `db/mariadb/init/01-schema.sql:70`
- 근거 코드:
  ```php
  $from   = " FROM v_item_public";
  ```
  ```sql
  WHERE i.status = 'A';
  ```
- 확신도: 확실
- 비고: `A`가 "공개"라는 의미는 스키마 주석에만 있다 (`01-schema.sql:26`). 같은 "공개 문항" 판정이 BR-02에서 뷰를 거치지 않고 따로 구현되어 있다.

### BR-02
- 규칙: 단원 목록의 단원별 문항 수는 `status = 'A'`인 문항만 센다.
- 근거: `units.php:17`
- 근거 코드:
  ```php
  (SELECT COUNT(*) FROM item i WHERE i.unit_id = u.id AND i.status = 'A') AS item_count
  ```
- 확신도: 확실
- 비고: BR-01과 같은 규칙이 두 곳에 다르게 구현되어 있다 (검색은 뷰 `v_item_public`, 단원 목록은 `item` 직접 조회 + 조건 하드코딩). 한쪽만 바뀌면 검색 건수와 단원별 문항 수가 어긋날 수 있다.

### BR-03
- 규칙: 검색 파라미터가 배열로 들어오면 첫 번째 값만 사용한다.
- 근거: `search.php:55`, `:59`, `:63`, `:67`, `:71`, `:75`, `:79`
- 근거 코드:
  ```php
  $q = is_array($params['q']) ? (string)reset($params['q']) : (string)$params['q'];
  ```
- 확신도: 확실
- 비고: 따라서 단원 · 난이도 · 태그는 각각 한 값만 조건으로 줄 수 있다 (다중 선택 없음).

### BR-04
- 규칙: 키워드 · 단원 · 난이도 · 태그 조건이 여러 개 주어지면 모두 `AND`로 결합한다.
- 근거: `search.php:44`, `:98`, `:118`, `:215`, `:218`, `:226`, `:244`
- 근거 코드:
  ```php
  $where    = " WHERE 1=1";
  $where .= " AND unit_code = ?";
  $where .= " AND level = ?";
  ```
- 확신도: 확실
- 비고: `OR` 결합 경로는 없다. 키워드 내부에서만 제목 · 지문을 `OR`로 묶는다 (BR-06).

## 2. 검색 조건별 규칙

### 키워드 (`q`)

### BR-05
- 규칙: 키워드는 앞뒤 공백을 제거하고, 100자를 넘으면 100자까지만 사용하며 경고를 표시한다.
- 근거: `search.php:85-88`, `search.php:494`
- 근거 코드:
  ```php
  $q = trim($q);
  if (mb_strlen($q, 'UTF-8') > 100) {
      $q = mb_substr($q, 0, 100, 'UTF-8');
  ```
- 확신도: 확실
- 비고: 매직 넘버 `100`. 같은 제한이 폼 입력 `maxlength="100"`(`:494`)에도 따로 있다.

### BR-06
- 규칙: 키워드가 비어 있지 않으면 제목 또는 지문에 키워드가 포함된(부분 일치) 문항만 조회한다.
- 근거: `search.php:90`, `search.php:97-98`
- 근거 코드:
  ```php
  $like = '%' . $q . '%';
  $where .= " AND (title LIKE ? OR stem LIKE ?)";
  ```
- 확신도: 확실
- 비고: 없음

### BR-07
- 규칙: 키워드에 `%`나 `_`가 있으면 이스케이프하지 않고 와일드카드로 그대로 적용하며 경고만 표시한다.
- 근거: `search.php:94-97`
- 근거 코드:
  ```php
  if (strpos($q, '%') !== false || strpos($q, '_') !== false) {
      $warnings[] = '키워드의 % 와 _ 는 와일드카드로 처리됩니다.';
  ```
- 확신도: 확실
- 비고: 이관 시 `LIKE` 이스케이프를 추가하면 결과가 달라진다.

### BR-08
- 규칙: 키워드가 한 글자이면 경고를 표시하되 검색은 그대로 수행한다.
- 근거: `search.php:91-93`
- 근거 코드:
  ```php
  if (mb_strlen($q, 'UTF-8') === 1) {
      $warnings[] = '키워드가 한 글자라 결과가 많을 수 있습니다.';
  ```
- 확신도: 확실
- 비고: 최소 길이 제한은 없다.

### 단원 (`unit`)

### BR-09
- 규칙: 단원 코드가 주어지면 앞뒤 공백을 제거하고 `unit_code`가 같은 문항만 조회한다.
- 근거: `search.php:109-110`, `search.php:118-120`
- 근거 코드:
  ```php
  $where .= " AND unit_code = ?";
  $types .= 's';
  $values[] = $unit;
  ```
- 확신도: 확실
- 비고: `unit` 테이블 콜레이션이 `utf8mb4_unicode_ci`이므로 (`db/mariadb/init/01-schema.sql:18`) DB 비교는 대소문자를 구분하지 않을 가능성이 높다. `:116` 경고 문구 "입력값 그대로 조회합니다"와 달리 소문자 `m5-1`로도 결과가 나올 수 있다 (실행 미확인).

### BR-10
- 규칙: 단원 코드가 형식 `^[A-Za-z][0-9]{1,2}-[0-9]{1,2}$`에 맞지 않거나 대문자가 아니면 경고만 표시하고 입력값 그대로 조회한다.
- 근거: `search.php:111-117`
- 근거 코드:
  ```php
  if (!preg_match('/^[A-Za-z][0-9]{1,2}-[0-9]{1,2}$/', $unit)) {
      // 형식이 달라도 그대로 조회한다 (결과는 대개 0건)
  ```
- 확신도: 확실
- 비고: 정규식의 자릿수 `{1,2}`가 매직 넘버다. 정규식은 소문자 첫 글자도 허용하지만 바로 아래에서 대문자 경고를 따로 낸다. 주석 "결과는 대개 0건"은 BR-09 비고의 콜레이션 때문에 소문자 입력에는 맞지 않을 수 있다.

### BR-11
- 규칙: 단원 코드가 `unit` 테이블에 없으면 "등록되지 않은 단원 코드" 경고를 표시하고 조회는 그대로 수행한다.
- 근거: `search.php:125`, `search.php:141-143`
- 근거 코드:

  ```php
  $stmt = $conn->prepare("SELECT name, grade FROM unit WHERE code = ?");
  if ($unitName === '') {
  ```

- 확신도: 확실
- 비고: 없음

### 난이도 (`level`)

### BR-12
- 규칙: 난이도가 빈값이면 `level < 5` 조건을 붙여 난이도 5 문항을 결과에서 제외한다.
- 근거: `search.php:211-216`
- 근거 코드:
  ```php
  // 난이도 값이 비어 있으면 전체 난이도 검색 (1~5 모두 포함)
  if ($level == '') {
      $where .= " AND level < 5";
  ```
- 확신도: 확실
- 비고:
  - **주석과 코드 불일치.** 주석은 "1~5 모두 포함"이지만 코드는 난이도 5를 제외한다 (ARCHITECTURE.md 미확인 목록과 같은 항목). 버그인지 의도인지는 코드로 판단할 수 없다.
  - 이 조건은 요약(`$summary`)에 추가되지 않는다. 다른 조건이 없으면 화면에는 "조건 없이 검색했습니다."(`:356`)가 표시되지만 실제로는 난이도 5가 빠진 결과다.
  - 폼의 "전체" 옵션 값이 `''`이므로 (`:192`) 폼에서 "전체"를 고르면 항상 이 경로를 탄다.
  - 매직 넘버 `5`.

### BR-13
- 규칙: 난이도가 `1`~`5` 한 자리 숫자이면 그 값과 같은 문항만 조회한다.
- 근거: `search.php:217-221`
- 근거 코드:
  ```php
  else if (preg_match('/^[1-5]$/', $level)) {
      $where .= " AND level = ?";
  ```
- 확신도: 확실
- 비고: 없음

### BR-14
- 규칙: 난이도가 빈값도 `1`~`5`도 아니면 경고를 표시하고 입력값을 정수로 변환한 값과 같은 문항을 조회한다.
- 근거: `search.php:223-229`
- 근거 코드:
  ```php
  $warnings[] = '난이도는 1~5 사이여야 합니다.';
  $where .= " AND level = ?";
  $values[] = (int)$level;
  ```
- 확신도: 확실
- 비고:
  - 주석(`:224`)은 "대개 0건"이라고 하지만, PHP `(int)` 변환 때문에 `03`, `3a`는 `3`이 되어 경고와 함께 난이도 3 결과가 나온다. `abc`는 `0`, `6`은 `6`이 되어 0건이다 (실행 미확인).
  - 같은 "난이도 1~5" 규칙을 등록 화면은 오류로 거부한다 (BR-36). 두 화면의 처리가 다르다.

### 태그 (`tag`)

- 규칙: 태그가 주어지면 앞뒤 공백을 제거하고, 그 이름과 정확히 일치하는 태그가 연결된 문항만 조회한다.

- 확신도: 확실
- 비고: `=` 비교이므로 `%`, `_`는 문자 그대로 비교된다 (BR-17).

### BR-16
- 규칙: 태그 이름이 50자를 넘으면 50자까지만 사용하고 경고를 표시한다.

- 비고: 매직 넘버 `50`. 스키마 `tag.name VARCHAR(50)`(`db/mariadb/init/01-schema.sql:37`)과 같은 값이다.

### BR-17
- 규칙: 태그에 `%`나 `_`가 있으면 "부분 일치를 지원하지 않는다" 경고를 표시하고 정확 일치로 조회한다.
- 근거: `search.php:237-239`
- 근거 코드:

  ```php
  if (strpos($tag, '%') !== false || strpos($tag, '_') !== false) {
  ```

- 확신도: 확실
- 비고: 키워드(BR-07)는 같은 문자를 와일드카드로 쓰고 태그는 쓰지 않는다.

### BR-18
- 규칙: 태그가 태그 목록에 없으면 "등록되지 않은 태그" 경고를 표시하고 조회는 그대로 수행한다.
- 근거: `search.php:251-260`
- 근거 코드:
  ```php
  if ($opt['value'] !== '' && $opt['value'] === $tag) {
  if (!$tagKnown) {
      $warnings[] = '등록되지 않은 태그입니다: ' . $tag;
  ```

- 확신도: 확실
- 비고: 등록 여부는 PHP `===`(대소문자 구분)로 판정하고, 실제 필터는 DB `=`(콜레이션 `utf8mb4_unicode_ci`, `01-schema.sql:40`)로 비교한다. 대소문자만 다른 태그는 "등록되지 않은 태그" 경고와 검색 결과가 함께 나올 수 있다 (실행 미확인).

## 3. 목록 정렬

### BR-19
- 규칙: 정렬 기준이 비어 있으면 난이도 내림차순, 같은 난이도에서는 문항 번호 오름차순으로 정렬한다.
- 근거: `search.php:317-320`
- 근거 코드:
  ```php
  case '':
      // 기본 정렬: 어려운 문항부터, 같은 난이도면 번호 순
      $orderBy = " ORDER BY level DESC, id ASC";
  ```
- 확신도: 확실
- 비고: BR-12와 겹쳐, 조건 없이 검색하면 기본 정렬 맨 앞에 와야 할 난이도 5 문항이 빠지고 난이도 4부터 나온다.

### BR-20
- 규칙: 정렬 기준이 `id`, `title`, `unit`, `level`, `created` 중 하나가 아니면 경고를 표시하고 기본 정렬(BR-19)을 사용한다.
- 근거: `search.php:322-326`
- 근거 코드:
  ```php
  default:
      $warnings[] = '알 수 없는 정렬 기준입니다. 기본 정렬을 사용합니다.';
      $orderBy = " ORDER BY level DESC, id ASC";
  ```
- 확신도: 확실
- 비고: 기본 정렬 SQL이 `:319`와 `:325` 두 곳에 중복되어 있다. `sort`, `dir`은 소문자로 바꿔 비교하므로 (`:266-267`) 대소문자를 구분하지 않는다.

### BR-21
- 규칙: 정렬 방향이 `asc`, `desc`가 아니면 무시하고(빈값이 아니면 경고), 기준별 기본 방향을 쓴다. `id` · `title` · `unit`은 오름차순, `level` · `created`는 내림차순이다.
- 근거: `search.php:268-273`, `:278-282`, `:286-290`, `:294-298`, `:302-306`, `:310-314`, `:330`
- 근거 코드:
  ```php
  if ($dir !== 'asc' && $dir !== 'desc') {
  if ($dir === 'desc') {
  if ($dir === 'asc') {
  ```
- 확신도: 확실
- 비고: `id` · `title` · `unit`은 `$dir === 'desc'`일 때만 내림차순(`:278`, `:286`, `:294`), `level` · `created`는 `$dir === 'asc'`일 때만 오름차순(`:302`, `:310`)이다. 화면 표시용 방향도 같은 기준으로 정한다 (`:330`).

### BR-22
- 규칙: 모든 명시적 정렬에서 동률일 때 보조 정렬은 정렬 방향과 무관하게 `id ASC`다.
- 근거: `search.php:287`, `:289`, `:295`, `:297`, `:303`, `:305`, `:311`, `:313`
- 근거 코드:
  ```php
  $orderBy = " ORDER BY title DESC, id ASC";
  $orderBy = " ORDER BY created_at DESC, id ASC";
  ```
- 확신도: 확실
- 비고: `sort=id`는 보조 정렬이 없다 (`:279`, `:281`).

### BR-23
- 규칙: `sort=unit`이면 단원 코드는 요청 방향으로, 같은 단원 안에서는 방향과 무관하게 난이도 내림차순 → `id` 오름차순으로 정렬한다.
- 근거: `search.php:294-298`
- 근거 코드:
  ```php
  $orderBy = " ORDER BY unit_code DESC, level DESC, id ASC";
  $orderBy = " ORDER BY unit_code ASC, level DESC, id ASC";
  ```
- 확신도: 확실
- 비고: 2차 키 `level DESC`는 `dir`의 영향을 받지 않는다.

### BR-24
- 규칙: 결과 표 머리글의 정렬 링크는 `id`, `title`, `unit`, `level`에만 있고, 현재 정렬 열을 누르면 방향을 뒤집으며, 정렬 중이 아닌 `level` 열은 첫 클릭에 내림차순이다.
- 근거: `search.php:392-417`
- 근거 코드:
